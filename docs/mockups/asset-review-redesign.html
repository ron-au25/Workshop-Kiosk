Why this layout

Problems in the current page

  • 7 stacked collapsibles (Components, Measure Performance, Overview, Inspection & Tasks, Work Plans, Parts) with equal weight: no order and no "start here".
  • Hidden coupling: tapping a Work Order card silently filters Measures + Work Plans. Plans and Parts sit in separate panels even though both belong to a WO.
  • Three selectors for the same thing: diagram zones, chip strip, sub-asset strip.
  • Green = "In progress" in today's legend, which reads as "done". There is no "complete" state.
  • Asset Overview (rarely changed) sits above the work. Charts sit above everything and don't follow the selection.
  • Inspection is form-first: every measure needs "+ New Measure" and a 7-field form.

What changes

  • One navigator (left rail): diagram + tree of wagon → wheelsets → sub-assets. Each row shows a 3-segment bar (Inspect / Repair / Sign-off).
  • Next-step banner: one sentence + one button telling the worker what to do now, computed from data.
  • 3-step flow per component: Inspect → Repair → Sign-off, replacing 5 panels.
  • Inspect = checklist: one-tap outcome (OK / Attention / Scrap) on each point, value inline. A finding gets an inline "Raise PM02" that prefills the task from the finding, linking measure to work.
  • Repair = WO-centric: each WO card holds its Work Plan steps and its Parts side by side. No filter mode. Next step highlighted.
  • Sign-off = gates: points recorded · every finding has a WO · steps done · parts consumed · serial present. Each failing gate jumps to the fix.
  • Details drawer: Asset Overview + serial edit move to a side drawer (ⓘ Details).
  • Wagon level: tapping the wagon gives a summary with per-wheelset cards, KPIs, and the cross-wheelset trend charts.
  • 4 status colours: grey not started · amber in progress · red needs action · green complete.

Open questions (not verified against org)

  • Expected measure points: mock assumes each component has placeholder points with no outcome yet (like today's PDF-checklist placeholders). Need to confirm they're reliably present.
  • Sign-off persistence: no field exists. Options: derived only (no write), set Asset.Status, or close the related WOs. Your call.
  • Linking a finding to its PM02 via Measure_Point__c.Work_Order__c: today that field holds the workpack id, so a PM02 link would overwrite it. May need a separate lookup.
  • Sample data, units (mm/°C) and the 14 mm scrap limit are invented for the mock.
