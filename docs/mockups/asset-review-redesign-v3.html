Design notes · v3

Changes from v2 (your feedback)

  • Findings are not tasks. Attention / Scrap is recorded on the measure itself: Comments__c, Review_Notes__c, Defect_Location__c, editable per row. A measure has no "Raise Task" button.
  • Raise Task = extra work the technician finds. It creates a WO on the selected asset, parented to the workpack. Work type is picked from all 86 WorkTypes in the org (searchable). The WO is marked as a raised task, and the Raised tasks view on the asset lists every raised WO on it, across workpacks.
  • Measures belong to the WO. The asset is derived from the WO, not picked separately.
  • Trend is per measure, across the asset's WOs over time: the same Component_Name__c on the same asset in earlier WOs, plotted by Update_Date__c. Tap a sparkline, and the side panel switches from PDF to trend.
  • Source document + Page # on each measure: the original PDF name and page. Tapping the 📄 chip opens that PDF at that page. Both are future fields, because Measure_Point__c has neither today. Options: a text field holding the file name, or the ContentDocument Id plus the name for display. WorkpackPdfProcessor already knows the source ContentDocument when it creates the points, so it could stamp them.
  • Config (org-wide) decides which fields show on the asset title tile, in the asset drawer (read or edit), and on the WO title tile. Try it with ⚙ Kiosk config.
  • Clock from any page: the clock button sits in the global header (kioskHeader). Tap it to clock in, out, or switch workpack. Auto clock-in on data changes stays as is. Today ensureClockedIn/autoClockOut/getActiveClock already exist, but the manual button is only in workOrderDetail, and the header only shows the timer. Clock stays at workpack level (ensureClockedIn resolves RootWorkOrderId). Per-child-WO time is a separate decision.
  • Sign-off: v2 invented a lock. Removed. The plans now show exactly what is in the org (see below).

Measure creation today: review (verified in repo + org, 2026-11-11)

  • assetReview → saveMeasurePoint: sets Work_Order__c = the workpack and Asset__c = the tapped asset. The measure never lands on the child WO that does the work. The 2 Aleen Reed points on 00012423 come from this path.
  • Reads by asset: getMeasurePointsByAsset and KioskBlocks query WHERE Asset__c IN …, so status depends on Asset__c being right.
  • HT-02 seed (2026-08-18 05:53:30, one insert, script not in repo): copied the 20 template points (Work_Type__c set, no WO) onto the child WOs. Asset__c is inconsistent: on 00012416–21 it is the truck, not the WO's component. On 00012424–31 it is blank, and only 00012415 matches its WO.
  • WorkpackPdfProcessor: PDF checklist items become points on the child WO with no asset and no type (blank placeholders).
  • InspectionChecklistController: WO only, no asset. WorkpackDemoGenerator: workpack WO + wheelset asset (wagon demo time series).
  • Flow RS_SFS_Create_Noti_Case_from_Measure_Point_Attention (active): when a point is updated to Attention Required and Comments is not blank, it creates a notification Case on the WO's asset. A finding with a comment therefore already notifies, so the mock nudges for a comment on every finding.
  • Proposal: the kiosk saves to the selected WO, and Asset__c = that WO's AssetId, stamped in Apex, not the UI. The seed data needs a one-off fix. Asset status and trend then read by Asset__c and stay correct. Not built.

Sign-off: what is in the org (00012423)

  • 🦺 Maintainer Checks: 7 plain steps (Bearing Keepers & Locking Tabs, Retainer Plates, Hand Brake, Yellow Cable Tie, RED TAG Removed, TSPB Valve Open, Walk-Around). These are wagon-style checks seeded onto a haul truck.
  • ✍️ Supervisor Sign-Off: 3 plain steps (Wheel Data Captured, Work & Time Confirmations, Final Signature & TECO). No ActionDefinition: no form, no signature capture, no status change.
  • 🚩 Raise Exception: Create Notification, Work Delay, Incident Form are data-capture flows. Request Assistance is a plain step.
  • Kiosk code has no sign-off logic (grep: nothing). Today "sign-off" is ticking 3 boxes. Who signs, what it locks, and whether it completes the workpack are undefined.

Open questions

  • Raised-task marker: no existing field fits. Work_Order_Type__c (Standard / Depot Repair, 3 of 4,207 WOs set) could take a new value Raised Task, or a new checkbox could be added. Both are schema changes.
  • Config store: no kiosk custom metadata exists. Field sets on Asset/WorkOrder exist (FSL Gantt/Crew) but carry no read/edit flag. Proposed: new CMDT Kiosk_Field_Config__mdt (Surface, Object, Field, Order, Editable). Not built.
  • Defect_Location__c values are wagon-only (Lower Lug, Palm, Knuckle Pin Hole…). HT-02 needs more values, or a value list per asset type.
  • MeasureValue_Type__c = Temperature/Pressure/Level/Width/Length/Depth. There is no Voltage or Flow, so electrical readings have no fitting type.
  • Values, history, parts, notes and the 3 synthetic levels under Diesel Engine are sample data.
