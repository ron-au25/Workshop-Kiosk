What the org shows (verified 2026-11-11)

  • 00012423 = Workpack for MEL-SEED Haul Truck HT-02 (Asset_Type SYST). Hierarchy: truck → 3 systems (Hydraulic / Mechanical / Electrical) → 9 components (PUMP, VALV, BRAK, MOTR, DRIV, GBOX, POWR, ELEC). 13 assets, 3 levels. No diagram art.
  • 16 child WOs, each on a component (an Inspection and a Repair per component). Measures, work plans and ProductRequired all hang off the WO. Many measure points have Asset__c = the truck root, not the component, and the PM01 children have blank placeholder points.
  • The workpack WO itself carries plans 🦺 Release to Traffic — Maintainer Checks, ✍️ Release to Traffic — Supervisor Sign-Off and 🚩 Raise Exception. So sign-off already exists as a work plan, and no new field is needed.
  • PDF "PRT Workpack 18/8/2026 — MEL-SEED Haul Truck HT-02" is linked to 00012423. 00012431 has a CMon PDF + 6 images.
  • pdfAnnotator LWC (repo + org) is already used by workExecution: pdf-url (base64), work-order-id, session-token, onsaved → KioskController.uploadAnnotatedPdf. Kiosk-safe (no shepherd URLs).
  • Notes & Codes (work notes history, cause/delay/damage codes) already exist in workOrderDetail.

Layout

  • Asset map (top): an icicle diagram. Each row is one hierarchy level (up to 6), and block width is proportional to sub-assets. Tap to select; assets with children zoom in, and the breadcrumb zooms out. No art needed, so it works for any asset type. Colour edge = rolled-up status, badge = open WOs. Wagons can switch to Schematic (the existing PNG with zones). Picking a diagram per Asset_Type__c is a config choice.
  • Work orders (left): WOs on the selected asset, optionally including sub-assets, grouped by asset. The WO is the unit of work, and selecting one opens its workspace.
  • WO workspace (right): Next-step banner + 4 tabs, all scoped to that WO: Measure (measure list with the WO's PDF side by side in pdfAnnotator, rows link to the PDF section) · Execute (work plans + steps in execution order, Raise Exception plan, sign-off plan locked until the others are done) · Parts (required vs consumed, consume, add) · Notes (notes history + codes).
  • Raise Task (not "PM02"): opens a defect WO form against the selected asset. Asset can be changed within the hierarchy, work type is picked, and the parent is the workpack. From a finding it prefills subject/description/asset and links the finding.

Open questions

  • Work type list for Raise Task: mock offers the work types already used in the workpack. Should it be filtered by asset type, or should there be a dedicated "Defect" work type?
  • Linking finding → defect WO: Measure_Point__c.Work_Order__c already holds the owning WO. A link to the raised task needs another lookup or a back-reference on the WO (not verified).
  • Measure ↔ PDF section: the "page" chip assumes a page/anchor per measure. No such field verified, so it could be manual or skipped.
  • 6-level depth under Diesel Engine (Fuel system → Injector bank → Injector) is synthetic to show depth. The real HT-02 has 3 levels. Measure values, step names and parts are sample data.
